## Quick start

```bash
npm install
npm start          # API on http://localhost:3001 and the site on http://localhost:5173
npm test           # unit + API tests, lint, build, HTML validation, links / i18n, CSS checks
npm run e2e        # clicks through all pages in Chrome (needs `npm start` running)
npm run audit      # axe-core on every page and theme, overflow and touch targets on 14 widths
```

`npm run api` and `npm run dev` start the two halves separately. The API answers after an artificial delay
of 300 ms (`API_DELAY`), so the loading states and the optimistic updates are visible. Every start of the API
copies `api/db.json` to `api/.data/` (git-ignored), so the committed seed never changes and a restart resets the data.

## Lab 4 — JavaScript, API and forms

### Functionality

- **Data only from the API.** There is no data array in the JavaScript. `api/db.json` (36 coins, 48 transactions,
  price series, profile, wallets) is generated by `npm run seed` and served by json-server 0.17.4.
- **Assets page.** Search with a 300 ms debounce (the request that is still running is cancelled), filter chips
  (all / holdings / gainers / losers / watchlist), category, sort by market cap / price / 24h change / name (also from
  the column headers), pagination from `X-Total-Count`. Everything is done by the server (`q`, `amount_gte`,
  `change24h_gte`, `_sort`, `_order`, `_page`, `_limit`). The state lives in the URL
  (`assets.html?filter=gainers&sort=price&page=2`): a link can be shared, Back works, a wrong value falls back to the default.
- **Asset details.** Hash router: `asset.html#/item/btc`, `#/item/btc/trade?type=sell` (opens the form), an unknown coin
  and an unknown route have their own messages, the old `?id=` address still works. The chart is drawn from the series of the API
  (six periods), the history tabs filter on the server.
- **Forms.** *Add transaction* and *Settings*: Constraint Validation API (`required`, `min`, `max`, `minlength`, `maxlength`,
  `pattern`, `type`), own rules through `setCustomValidity` (cannot sell more than you hold, no date in the future),
  messages tied to the fields with `aria-describedby` / `aria-invalid`, focus goes to the first wrong field,
  a draft in `localStorage`, `POST /transactions` and `PATCH /profile`; the server validates again and answers `422`
  with the fields that are wrong.
- **Optimistic star.** The star of a coin changes at once, `PATCH /coins/:id` goes out in the background, on an error the
  star goes back and a message says why.
- **Cache, states, router.** `RequestCache` (TTL 60 s, mirrored to `sessionStorage`) is cleared after every `POST` / `PATCH`
  of the collection; every list has loading (skeletons, `aria-busy`), error (message and *Try again*) and empty states.
  A GET that got no answer is repeated twice, which is what a sleeping free host needs.
- **Extras.** CSV export of the assets and of the transactions, wallets (`POST /wallets`), photo preview, `Ctrl K` search.

### API (`api/server.js`)

json-server is read-only for everybody; the server lets through only the writes the app needs and validates them.

| Request | Meaning |
|---|---|
| `GET /coins?q=sol&category=DeFi&change24h_gte=0.01&_sort=price&_order=desc&_page=2&_limit=10` | list, `X-Total-Count` in the answer |
| `GET /coins/btc`, `/details/btc`, `/charts/btc`, `/coins/btc?_embed=transactions` | one coin and what belongs to it |
| `GET /transactions?coinId=btc&type=buy&_sort=date&_order=desc`, `?_expand=coin` | history |
| `GET /profile`, `/market`, `/portfolio`, `/wallets` | one-record resources and the wallets |
| `POST /transactions` | new transaction (validated: coin, type, amount, price, fee, date, note) |
| `PATCH /coins/:id` | `watched`, `amount`, `avgBuy`, `costBasis`, `value` only |
| `PATCH /profile`, `POST /wallets` | settings, a wallet (at most 6) |
| anything else that writes | `405`; a wrong body `422 { error, fields }` |

### Publishing the API (Render, free plan)

GitHub Pages serves only static files, so the API runs on its own host. `render.yaml` describes it:

1. Sign in on <https://render.com> with GitHub, **New > Blueprint**, pick the `coinfolio` repository, *Apply*.
2. When the service is live, copy its address (for example `https://coinfolio-api.onrender.com`).
3. `cp .env.production.example .env.production`, put the address into `VITE_API_URL`, then `npm run deploy`.

The free plan puts the service to sleep after 15 minutes without requests; the first request then takes up to a minute
(the interface shows skeletons and the message *The server is waking up*). The data resets whenever the service restarts.
Without `VITE_API_URL` the site talks to `http://localhost:3001`, which works from the preview too while `npm run api` is running.

## How it is built

- **Vite** multi-page build (`vite.config.js`), `base: "./"` so the build works on any static host; the page code is split per page.
- **EJS** (`build/ejs-pages.js`) renders the shells of the pages: header, footer, headings, the place for the data
  (`src/templates/partials`). Only text and navigation are known at build time (`src/data/site.js`).
- **i18n**: markup text carries `data-i18n`, text rendered by JavaScript uses `t(key, vars)`; dictionaries
  `public/locales/en.json`, `uk.json`. The UI is English; `?lang=uk` or the language in the settings switches to Ukrainian.
- **Security**: values from the API go through the `html` template tag, which escapes them (a note `<b>x</b>` is shown as text), no `innerHTML` with raw data.

## Lab 3 — SCSS and responsive layout

### Functionality

- **Four responsive pages** (mobile first, breakpoints 360 / 768 / 1280 px, nothing overflows from 320 to 1920 px):
  phones get a fixed bottom tab bar with a centre "+", cards instead of tables and swipeable strips;
  from 1280 px the header has pill navigation and search, tables replace cards and the asset page and
  profile become two columns (8 + 4 columns of the grid).
- **Dark and light theme.** `data-theme` on `<html>` swaps the CSS custom properties; the choice
  (dark / light / system) is stored in `localStorage` and can be changed on the profile page.
- **Interactions without JavaScript:** period switches, filter chips, type switch and theme switch are
  radio inputs; the settings toggles are `role="switch"` checkboxes; hover, focus and entrance animations
  use only `opacity` / `transform` and respect `prefers-reduced-motion`.
- **Own 12-column grid** (`row()` / `col()` mixins with real gutters) next to CSS Grid where a layout needs it
  (profile page areas, header, forms).

### Style structure (architecture 7-1)

```
src/scss/
  main.scss        only @use, no rules
  abstracts/       _variables (tokens from Figma), _functions, _mixins, _placeholders; emits no CSS
  vendors/         self-hosted variable fonts (Inter, Space Grotesk)
  themes/          _default (dark), _light: colour roles as CSS custom properties
  base/            reset, typography, utilities, animations, print
  layout/          grid, header, nav (tab bar / pills), search, footer, page shell
  components/      one file per BEM block (48 blocks): button, card, field, switch, price, history, ...
  pages/           page-level composition only: dashboard, assets, asset-details, profile
```

- **Variables:** colours, type scale, spacing (4 px steps), radii, shadows, durations and breakpoints are
  Sass maps in `_variables.scss`; components never contain HEX values or raw pixel spacing.
- **Functions:** `rem()`, `space()`, `radius()`, `color()`, `duration()`, `breakpoint()`, `z()`,
  `col-width()`, `tint()` / `shade()` (the light palette is derived from the dark one).
- **Mixins:** `media-up()`, `flex()`, `row()` / `col()`, `text-style()`, `transition()`, `hover()`,
  `focus-ring()`, `scroll-strip()`, `metric-panel()`, `meter-bar()`, `tx-tones()`, `reveal()`.
- **Placeholders + `@extend`:** `%surface`, `%overline`, `%visually-hidden`, `%list-reset`, `%row`,
  `%col-12` and one `%type-*` placeholder per Figma text style, so repeated blocks are compiled once.
- **BEM** (`block__element--modifier`, mixes such as `balance card`) is enforced by Stylelint together with
  nesting depth <= 2, <= 2 compound selectors, no IDs, no `!important` in blocks, alphabetical properties.

### Known differences from Figma

- The phone layout shows the period switch above the chart (document order) and keeps all four rows of the
  position card; the Figma phone frame hides one row.
- Input icons and the donut centre label come from the design but need extra markup; the donut label was added,
  field icons were left out.
- The chart images are exported dark PNGs, so they stay dark panels in the light theme.
